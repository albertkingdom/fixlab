# 第 6 篇：第一次完整的真模型修復

> 對應任務：bootstrap-agent-core 的 3.12。
> 完成度：用真模型對範例專案跑了兩次完整的修復，兩次都修好了。這是**觀察，不是通過門檻**，結果照實記錄。

前面幾篇一塊一塊做好零件：解析工具呼叫、讀檔與列檔案、改檔、跑測試，再用迴圈接起來。這一篇回答一個很簡單的問題：**接起來之後，真的模型能不能把一個 bug 修好？**

做法很單純：把範例專案 timelog 複製到暫存目錄，交給真模型，只說「測試失敗了，找出原因並修好」，看它自己怎麼做。

## 設定

範例專案裡藏了一個 bug：解析 `1h30m` 時只取第一個單位，所以 `weekly_total` 算出 3.75，而不是 4.25。測試的訊息只寫 `3.75 != 4.25`，沒有指出原因，bug 在另一個檔案裡（測試 → 彙整 → 解析）。

指令（因為 `fixlab` 會直接修改指定的目錄，所以先複製一份）：

```
cp -R tests/fixtures/timelog /某個暫存目錄/timelog-try
fixlab /某個暫存目錄/timelog-try
```

這次用的條件（AGENTS.md 守則 3 要求的欄位都在這裡）：

| 項目 | 內容 |

| 模型 | `qwen/qwen3.5-9b`，經 OpenRouter |
| 供應商 | Venice（OpenRouter 轉給哪家由它決定，兩次都是 Venice） |
| 量化方式 | 未知（OpenRouter 沒有提供） |

模型有四個工具：列檔案、讀檔、改檔、跑測試。它沒有任何能執行任意指令的工具。

-    units = [re.match(r"(\d+)([hm])", text).groups()]

第 2 次比較短：

| 步 | 做了什麼 |

最後的說明：

```
The issue was in `timelog/parser.py`. The original code used `re.match()` which only matches at the
start of the string, so for "1h30m" it would only capture "1h" and ignore "30m".

I fixed it by using `re.findall()` which correctly captures all digit-letter combinations in
multi-unit patterns like "1h30m".

The tests now all pass.
```

幾個值得注意的地方：

- **它先跑測試，再讀程式。** 兩次都是這樣。有了跑測試的工具，模型的第一步就拿到了失敗訊息，再順著它往下找。
- **改檔一次成功。** 舊字串橫跨多行，包含縮排和 `\d` 的跳脫字元，沒有把行號抄進去，沒有寫錯。第 1 次只換那一行，第 2 次換整個函式，兩種做法都行得通。
- **改完自己驗證。** 兩次都是改檔後馬上跑測試，確認通過才說結論。
- **沒有碰測試檔。** 前面（第 4 篇）沒有跑測試的工具時，模型曾經去改測試檔；這次有了跑測試的工具，完全沒有這種繞路行為。

## 第 1 次多出的幾步

第 1 次是 11 步，比第 2 次多三步（見上面的表）：

- **第 3 步猜了一個不存在的目錄。** 它要求列出 `src`，工具回報「找不到 `src`」，第 4 步它就改成列出全部檔案。一次失敗，沒有造成問題。我猜它是在套用常見的 `src/` 版面，這是模型的行為，不是我們的問題。
- **第 9 步重複跑了一次相同的測試**，同時附上說明。多花一步，沒有害處。
- **空回覆**（第 10 步），下一節。

## 兩次都出現的問題：空回覆

兩次都在模型驗證完畢、通過測試之後，出現了一個**空回覆**：沒有文字、沒有工具呼叫，只有思考內容。

| | 第 1 次第 10 步 | 第 2 次第 7 步 |
|---|---|---|
| 結束標記 | `stop`（模型自己停下） | `stop` |
| 輸出 token | 11 | 66 |
| 思考內容長度 | 43 字元 | 274 字元 |
| 文字內容 | 無 | 無 |

迴圈的規定是：空回覆不能算「完成」，要回饋給模型再試一次。當時的回饋是：

```
Your tool call was invalid: empty response (no text and no tool call). Please call a tool with valid arguments.
```

問題在這句話。這個時間點，模型其實**已經做完了**，只差說一句結論。回饋卻叫它「呼叫工具」，措辭有誤導。模型下一個回覆才給出結論，各白花了一步。

這是**我們的訊息寫得不對**，不是模型能力的問題。我把它歸在「工具回饋的缺陷」。事後已經改成：

```
Your reply was empty. If you are finished, reply with a short final message; otherwise call a tool.
```

新措辭涵蓋兩種情況。規格的「空回覆」情境加了一條，測試也補上了。要老實說：改完之後我**沒有**再讓真模型重跑，所以「新措辭能不能真的省掉那一步」還沒驗證。

為什麼會有空回覆？我的推測是模型把輸出都花在思考上，來不及產出文字就停了，但這只是從數字（輸出 token 很少、思考內容有長度、沒有文字）做的推測，沒有再驗證。

另外有一個新的現象：重跑第 1 次在改檔之後**連續跑了三次一模一樣的測試**（第 7、8、9 步），然後才說結論。三次的輸出完全相同，白花了兩步。目前沒有偵測重複呼叫的機制，設計上留到階段 2。這再次說明同一個模型、同一題，每次的行為不完全一樣。

## 這次不能說明什麼

- **兩次、一個模型、一道題**，不能說這個模型「通常」修得好，也不能拿去和別的模型比。
- **題目簡單**：bug 在單一檔案、一行就能修、測試訊息已經給了差異的數字。
- **兩次都成功，不代表穩定**：每次輸出都有隨機性，這個介面又沒有設定隨機種子的方式。
- **思考模式開著**，無法判斷關掉會怎樣。

這次的目的只是確認：**整條流程（找、改、驗證、回報）能運作，而且回報是可信的**（最後的測試和差異，都是入口自己算的，不靠模型怎麼說）。穩定度、多模型比較、題目難度，是階段 3 的事。

## 怎麼重現

```
cp -R tests/fixtures/timelog /某個暫存目錄/timelog-try
export OPENAI_BASE_URL=https://openrouter.ai/api/v1
export OPENAI_API_KEY=你的金鑰
export FIXLAB_MODEL=qwen/qwen3.5-9b
fixlab /某個暫存目錄/timelog-try
```

每一步的完整紀錄（模型說了什麼、呼叫了什麼、拿到什麼）可以在本機的 `runs/3.12-qwen3.5-9b-20261017/` 看到，不進版本控制。要自己存這種紀錄，需要另外寫一小段程式包住入口，把每一步的紀錄寫成檔案；目前入口本身還沒有這個功能，那是階段 2 的紀錄功能。

## 參考來源

看過高見龍 KeSi 第 13 天的實戰示範（`examples/day13/`，MIT 授權，Copyright (c) 2026 Eddie Kao，commit `dfa0cd0`，2026-10-17 查證）。

- **他的做法**：示範專案是「會員訂單試算」，bug 是折扣門檻的比較應該用 `>=` 卻寫成 `>`；出題的三個原則是「bug 不在測試檔指到的那個檔案裡（要追兩跳）、錯誤訊息看不出原因、放兩個無關的檔案當干擾」；示範腳本會印出起點的測試狀態、全程、終點的測試狀態與磁碟上的差異，最後印帳單；`--no-shell` 的選項把執行指令的工具拿掉，對照「沒辦法跑測試的 agent 怎麼收尾」。他用的是 Claude Haiku 4.5，一次約 $0.04。
- **這個專案與他的相同之處（要老實說）**：題目也是兩跳、錯誤訊息不透露原因、有干擾檔，AGENTS.md 對 benchmark 的需求也是這三點；入口結束後印差異、再跑一次測試，與他示範腳本的做法是同樣的想法；之後計畫做的「有／沒有跑測試工具」的對照實驗，與他的 `--no-shell` 是同一類。我無法排除這些是受他影響的。
- **不同之處**：領域（工時解析對訂單試算）與 bug 類型（解析邏輯只取第一個匹配，對比較運算子寫錯）是自己設計的；他的差異比對的是寫死在示範裡的原始檔案內容，這個專案對任意目錄在執行前拍快照；這個專案用開源模型，一次不到 $0.002。
- **他提醒的一件事，這次也驗證了**：「測試變綠有很多種作弊方式，把測試改掉也算一種，所以每次跑完都要看它到底動了什麼。」第 4 篇那次模型確實改了測試檔。
