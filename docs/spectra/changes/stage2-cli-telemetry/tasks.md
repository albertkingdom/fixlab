- [x] 1.2 「寫入唯讀檔案的嘗試用 protected_write 旗標」：寫入唯讀檔案被擋時旗標是 `blocked` 加 `protected_write`，路徑逃逸只有 `blocked`，對應 Writes to read-only files are flagged 的三個情境（edit_file 改測試檔、write_file 新建測試檔、`../outside.py`）；迴圈把它計入 `protected_write_calls`，對應 Protected writes are counted。驗證：tests/test_isolation.py 新增三個測試、tests/test_loop.py 新增一個計數器測試；既有測試中對唯讀檔案斷言旗標的地方（isolation 九處、test_cli 一處）改成新旗標，路徑逃逸的斷言不變；黃金 trace 被擋下那一步多一個 `protected_write`、計數器多 `protected_write_calls`，重新產生後 git diff 只能多出這兩樣，並更新 `test_golden_covers_the_intended_cases` 的斷言。

## 3. 互動模式與權限提示

- [x] 3.1 「互動模式用 -i，不設子命令；斜線指令只有 /reset 與 /exit」並保留對話：`fixlab PATH -i` 顯示 `fixlab> `，空行忽略，`/exit`、Ctrl-D、提示字元上的 Ctrl-C 以 0 離開，`/reset` 清空對話並印 `conversation cleared`，其他行是任務；同一個 session 內每個任務接續前面的對話，不自動再跑一次測試，每個任務各寫 `task_start` 與 `task_end`（`final_tests` 與 `changed_files` 為 null）。對應 Interactive mode is entered with -i（沒有 `-i` 不變、缺模型退出碼 2）、The conversation is kept for the session（後續請求帶前面的訊息、新 session 是空的）、Slash commands and empty lines（重設後任務序號繼續、空行不送請求）與 No automatic final test run in interactive mode，以及 The model's final reply is shown（`done` 時先印模型的最後回覆，再印 `stop reason:` 那一行）。驗證：tests/test_interactive.py 以注入的輸入與假 client 對應每個情境各一個測試。
- [x] 3.2 「中斷時丟棄該任務新增的訊息」：Ctrl-C 打斷執行中的任務時，把對話截回任務開始前的長度，印出提示，寫 `stop_reason` 為 `interrupted` 的 `task_end`，回到提示字元，下一個任務的請求裡沒有缺少結果的 `tool_calls`。任務以 `error` 結束（請求失敗）時同樣丟掉該任務的訊息，`max_steps` 與 `stuck` 則保留；對應 Interrupting a task discards its messages 與 A task that fails with a request error is discarded（失敗前有成功的任務、跑滿步數仍保留）。驗證：tests/test_interactive.py 讓假 client 在第二次請求時丟出 `KeyboardInterrupt`、或丟出一般例外，檢查訊息長度、提示文字、事件檔的 `task_end` 與下一個請求。
- [x] 3.3 互動模式的提示函式：只對 `edit_file`、`write_file`、`run_tests` 提問，摘要格式與 `Allow? [y]es / [a]lways for this tool / [N]o: `，回答 `y`、`a`、其他一律拒絕（含空行與輸入結束），`a` 只對同一個工具在這個 session 內有效，字串最多顯示 200 字元；一次性模式不傳 `confirm`。對應 Interactive mode asks before changing files or running tests（讀取不問、回答對照表、always 依工具、長字串截斷）與 One-shot mode never asks（標準輸入關閉照常跑）。驗證：tests/test_interactive.py 與 tests/test_cli.py 各情境一個測試，輸入用注入的函式。
